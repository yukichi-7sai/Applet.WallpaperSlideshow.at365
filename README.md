# Applet.WallpaperSlideshow.at365

WallpaperSlideshow.at365をAppDockへ移したWindows用Appletです。**v0.7.0 / AppDock v0.66.1以降が必要**です。

0.4.5では「停止」と「更新間隔」の設定をCodex連携へ公開します。停止のON/OFF/切り替えコマンドは設定定義から自動生成され、ショートカットにも割り当てられます。設定変更にはコマンド実行・設定変更の両許可が必要です。「次の壁紙」はコマンド実行許可だけで利用できます。

## 導入・更新

0.5.0から合成画像をメモリから背面ウィンドウへ表示し、Windowsの壁紙設定を変更しません。表示用BMPの保存も行いません。0.4.2からエラーログはAppDockの「ログ」ページと、このAppletの詳細にある「ログ」タブに表示します。旧APPDATA内のファイルや以前の`errors.log`は自動移動・削除しません。壁紙フォルダーの元画像とAppDockの共有設定はこれまでどおりです。

1. AppDockをトレイの「終了」から完全終了します。
2. 配布物の `extension.json`、`Applet.WallpaperSlideshow.at365.exe`、`web`フォルダーを、AppDock.at365.exeの隣の `extensions/Applet.WallpaperSlideshow.at365/` に配置します。更新時も配布物一式をそろえて置き換えてください。
3. AppDockを起動し、「Applet」一覧で有効にします。操作やキーの割り当てはAppDockから行います。

利用するPCにはAppDockの動作環境が必要です。詳細は[AppDockの導入案内](../AppDock.at365/README.md)を参照してください。

このAppletの配布EXEには必要なランタイムが含まれています。元のWallpaperSlideshowと同時に再生しないでください。

## 設定

AppDockの「設定」→「Applet.WallpaperSlideshow.at365」で、JSONを直接書かずに設定できます。



- 「モニターごとの画像設定」は共通の一覧で表示します。番号・画像ソースフォルダー・表示モード・タイル枚数を確認でき、歯車で詳細を編集します。「モニターを追加」も同じダイアログを使い、OKで保存、キャンセルで入力を破棄します。
- モニター番号は左から右、同じX位置では上から下の画面順です。並べ替えボタンで設定を割り当てる順序を変更できます。ゴミ箱から削除する際は確認が表示されます。
- モニターごとに画像ソースフォルダーを複数追加でき、Windowsのフォルダー選択も使えます。各64件まで。旧設定の単一`Folder`やJSON文字列も読み取り、編集時に`Folders`へ移します。
- **表示モード・タイル枚数・上下左右のPaddingはモニターごとの設定**です。Fill / Fit / Stretch / Center / Tile、タイル1～64枚、Padding 0～65535px。実際の画面サイズを超える余白はエラーにします。
- 更新間隔、タイル間余白、履歴の保存件数、サムネイルの幅・高さ、ファイル名の表示文字数をフォームで変更できます。元アプリの範囲（サムネイル1～2048px、ファイル名1～1024文字）を維持しています。
- 「最近使った壁紙の1ページの表示件数」は**既定4件、1～1000件**です。モニターごとの履歴保存件数（既定30件、0～1000件）とは独立しています。

フォルダー内のJPEG / PNG / BMPとサブフォルダーの画像を使います。重複フォルダーや親子フォルダーの画像を重複排除し、1巡するまで同じ画像を選びません。存在しないフォルダーや共有の復旧を監視し、アクセスできるほかのフォルダーは使えます。サブフォルダーのジャンクション・シンボリックリンクはたどりません。絶対パスを推奨しますが、旧設定の相対パスもAppletの配置フォルダーを基準に解釈します。

設定はAppDockの`settings.json`内の`extensions["at365.wallpaper-slideshow"].settings`へ保存し、元アプリの設定は変更しません。不正な画像設定はログとパネルに表示し、前回の有効設定を維持します。旧`Mode`の数値表現も引き継ぎます。

## デスクトップへの表示

画像はデスクトップのアイコンより後ろに表示します。Windowsの背景を「画像・スパン」に準備する必要はありません。画像切り替えによる壁紙設定の書き換えと表示用BMP保存を廃止したため、旧prepare-backgroundコマンド・ボタンは削除しました。既存の割当は自動で別操作へ振り替えません。「Windowsの背景設定を開く」は、停止中に見えるWindows側の背景を確認するために使えます。

背面への配置はExplorerの構成に依存します。接続できない場合は操作画面に再接続待ち・表示エラーを表示し、Windowsの背景をそのまま維持します。「次の壁紙」で再試行できます。旧版利用前の壁紙は記録していないため、自動復元は行いません。画像を保持するためのメモリは表示解像度に応じて使用します。

## 遅延開始とコマンド

AppDock共通の「開始までの秒数」は**既定30秒**。有効化・AppDock起動・Applet再起動から指定秒数後に、Appletのプロセス自体を起動します。0で即時、最大86400秒。開始待ちの画面に予定時刻と「今すぐ開始」を表示します。無効化・AppDock終了で予約を取り消し、待機中の秒数変更ではそこから待ち直します。

コマンドはAppDockのパレット・ピン留め・ショートカットで使用します。生成コマンドはAppletの起動前からキーを設定できますが、実行は有効・稼働中に限ります。Appletを有効化し、必要なら「今すぐ開始」を押してください。旧start/stop/toggle/resume/pauseは廃止しました。既存のキー・トレイ・ジェスチャー割当は、新しいコマンドへ割り当て直してください。自動移行は行いません。

| ID末尾 | 操作 |
| --- | --- |
| `settings.paused.off` | 開始／再開。手動停止を解除し、再生中なら維持 |
| `settings.paused.on` | 停止。現在の壁紙を消去し、停止状態を保存 |
| `settings.paused.toggle` | 手動停止状態を反転して保存 |
| `next` | 次の壁紙に更新 |
| `history` | 最近使った壁紙の独立ページを開く |
| `home` | 履歴ページを閉じ、ホストのApplet管理へ戻る（旧ホストではApplet詳細） |
| `data` | データフォルダーを開く |
| `background-settings` | Windowsの「個人用設定 → 背景」を開く |

IDの接頭辞は`at365.wallpaper-slideshow.`です。旧`resume`/`pause`の別名も廃止し、生成コマンドへ統一しています。画像ごとの「履歴1を開く」等はコマンド登録せず、履歴ビュー専用のボタンで処理します。

手動停止は保存され、ロック解除で勝手に再開しません。ロック・リモート接続による停止は手動停止と独立しています。停止中の「次の壁紙」は切り替えず、開始もロック・リモート接続による停止を解除しません。不正な画像設定があっても前回の有効設定で開始・停止できます。停止・無効化・終了では表示ウィンドウと画像メモリを解放し、その時点でWindowsに設定されている背景が見えます。Windowsの壁紙設定は変更しません。

## 最近使った壁紙

リボンの「最近使った壁紙」、または「最近使った壁紙を開く」コマンドで開きます。画像カードとシンプルな操作ボタン、ページ送りを備え、本体の明暗テーマに追従します。Appletの説明には通常の壁紙操作と状態を表示します。履歴の表示先はApplet設定から本体内／別ウィンドウを選べます。

0.6.0で「壁紙履歴の前のページ」「壁紙履歴の次のページ」コマンドを廃止しました。ページ内の前後ボタンを使ってください。保存済みのキーやピンは自動削除せず、廃止コマンドの割り当ては実行できない項目として保持します。

履歴の上部にある**モニター1 / モニター2…**で切り替えます。各モニターの件数とページ位置を別々に扱います。履歴は実行中だけパスを保持し、Applet終了で消えます。0件設定で履歴を無効化できます。

各画像にサムネイル、解像度・ファイルサイズ、元ファイルパスのツールチップ、「開く」「削除」を表示します。AppDockの画像ライブラリーと共通のカードを使い、ページ内の「画像サイズ」で大きさを調整できます。サイズはこのPCで記憶し、サムネイルの生成解像度・壁紙の再生設定・ライブラリーの表示サイズには影響しません。

サムネイルをクリックすると、ページの幅・高さの60%のプレビューを開きます。周囲のグレーの背景、閉じるボタン、Escで閉じられます。削除は対象の元ファイルを確認する画面を表示し、「ごみ箱へ移す」で実行します。キャンセルも可能です。成功時は同じパスをすべてのモニターの履歴から除き、表示を更新します。古いページのボタンでは別の画像を操作できません。

削除失敗時はファイルと履歴を維持します。ごみ箱へ移せない環境ではエラーになります。

## データの保存先

履歴カードの表示サイズはAppDockのPC専用保存先の`storage/at365.wallpaper-slideshow/gallery-view.json`に保存します。初めてサイズを変更したときに作成し、再起動後も復元します。保存できなかった場合は画面に表示し、「保存を再試行」でやり直せます。破損・未知形式のデータは自動で上書きしません。

表示画像はメモリ内で合成し、表示用BMPやWindowsのThemesキャッシュへの保存は行いません。履歴サムネイルはAppDockのPC専用保存先のcache/panel-images、エラーログはAppDockへ保存します。ページ変更・操作画面へ戻る・終了時にサムネイルを削除します。旧Local/Roaming領域や旧BMPは自動移動・削除せず、「データフォルダーを開く」は従来フォルダーを開きます。

## 手動設定の例・更新の確認

保存されるモニター設定の形式例です。通常の設定操作には上記のフォームを使ってください。

```json
[
  { "Folders": ["C:/Wallpapers/Art", "C:/Wallpapers/Photos"], "Mode": "Tile", "TileCount": 13, "PaddingLeft": 1, "PaddingRight": 1, "PaddingTop": 1, "PaddingBottom": 40 },
  { "Folders": ["C:/Wallpapers/Portrait"], "Mode": "Fit", "PaddingLeft": 1, "PaddingRight": 1, "PaddingTop": 1, "PaddingBottom": 1 }
]
```

AppDock 0.26.18未満では利用できません。更新元の既定値は`github:yukichi-7sai/Applet.WallpaperSlideshow.at365`です。AppDockの「バージョン情報・更新」ページから、正式リリースを確認して更新できます。起動時の更新確認ではダウンロード・適用を行いません。

## AppDockからの更新

AppDock 0.22.0以降では「設定 → バージョン情報・更新」の一括更新、またはこのAppletの個別更新ボタンを利用できます。配布元が`update.json`と`update.zip`を提供している場合に対応します。更新元は「インストール済みのApplet」の「更新元の設定」で変更し、保存してください。ローカルフォルダー・UNC・HTTP(S)・GitHub Releaseに対応し、「既定に戻す」も利用できます。

更新内容を確認して再起動すると配布ファイル一式を交換します。AppDock側の設定・有効状態・保存データは保持します。詳細は[AppDockの更新操作](../AppDock.at365/README.md#アップデート)を参照してください。

開発・ビルドについては[開発ガイド](DEVELOPMENT.md)を参照してください。

## 公開設定の拡充（0.4.6）

Codexから停止・更新間隔に加え、タイル間の余白、履歴件数、サムネイルの幅/高さ、ファイル名の表示文字数、1ページの表示件数を取得・変更できます。履歴件数を減らすと実行中の古い履歴は削られますが、元画像は削除しません。モニターごとの画像フォルダーや表示方法は設定画面から編集してください。必要な本体版は0.26.30です。

## 共通の設定画面

AppDockの「設定」またはApplet詳細の「設定」タブで、スライドショー・モニターと画像・履歴の表示・Windowsの背景のカードから編集できます。本体と同じテーマ・入力欄・自動保存を使い、起動待ちは末尾の共通カードにあり、ページを持つAppletでは表示方法も設定できます。既存の設定値・コマンドIDは引き継ぎます。履歴とWindows背景の操作は見出しを押すと開き、横断検索からも対象項目へ移動できます。
