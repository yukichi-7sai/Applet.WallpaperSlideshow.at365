# 壁紙履歴ページ

共通基盤の追加は[.NET AppletのHTML/JavaScriptページ連携](../../AppDock.at365/docs/applet-pages.md)、既存の表示と設定は[Appletページ](../../AppDock.at365/docs/applet-pages.md)を参照する。本書はApplet固有の画面・処理・廃止コマンドを定義する。

## 決定と作業範囲

- 「最近使った壁紙」を独立したlocalページとして登録する。リボンと既存コマンドを入口にする。
- Applet詳細の説明から、履歴へのボタン、履歴一覧、モニター切り替え、履歴のページ送り、画像削除確認を取り除く。説明には現在の状態・エラーと通常の壁紙操作を残す。
- `at365.wallpaper-slideshow.history`はIDを保ち、表示名を「最近使った壁紙を開く」、処理をページを開くコマンドへ変える。
- 「壁紙履歴の前のページ」「壁紙履歴の次のページ」は明示された廃止対象。`history.previous`と`history.next`のコマンド登録を削除する。ページ内の前後ボタンはページ操作APIから呼び、コマンドとして再登録しない。
- .NETで既存のエンジン・履歴・サムネイル生成・ファイル操作を継続し、HTML/CSS/JavaScriptで履歴を描画する。

共通基盤と独立ページを同じ作業の段階として実装する。発行までを対象とし、commit、push、Release、実利用先への配置は別の依頼で扱う。

## ページ登録とコマンド

履歴は常に1画面なので、動的な登録・解除ではなく固定の`manifest.pages`を使う。動的ページの.NET対応は共通基盤で提供し、このAppletでは`dynamic-pages` capabilityを要求しない。

以下は実装時に追加するmanifestの部分例。minimumHostVersionは共通APIを実装した本体版に合わせる。

```json
{
  "capabilities": ["ui", "settings", "local-images", "pages"],
  "commands": [{
    "id": "at365.wallpaper-slideshow.history",
    "title": "最近使った壁紙を開く",
    "activateOnExecute": true
  }],
  "pages": [{
    "id": "history",
    "title": "最近使った壁紙",
    "icon": "image",
    "source": "local",
    "ui": "web/history.html",
    "openCommand": "at365.wallpaper-slideshow.history",
    "defaultDisplay": "page"
  }]
}
```

既存の他コマンド・capability・設定定義は実装時に統合して残す。ページの安定したリボンIDは`page:at365.wallpaper-slideshow:history`。表示先、配置、非表示、別名は本体の標準機能を使う。

| コマンドID末尾 | 変更後 |
| --- | --- |
| `history` | `Pages.OpenAsync("history")`。既存Viewがあれば前面に出し、開くだけでページ位置を初期化しない |
| `history.previous` | 廃止。保存済み割り当ては保持し、実行できない項目として本体の既存契約で扱う |
| `history.next` | 廃止。同上 |
| `home` | IDと「壁紙の操作に戻る」を保つ。履歴用の状態・画像を解放し、`Pages.DisposeAsync("history")`で履歴Viewを破棄してから、共通の`Ui.OpenDetailsAsync`で自身の説明を開く |
| `next`、`data`、`background-settings`、`settings.paused.*` | 既存の処理とIDを維持 |

廃止した2コマンドのキー・ピン・トレイ・ジェスチャー・リボン設定を自動削除・再割り当てしない。画像ごとの操作やモニター切り替えもコマンドとして公開しない。既存の外部公開宣言を増やさない。

`activateOnExecute:true`により履歴の明示実行は標準の起動経路を使う。起動失敗・開始待ち・無効状態の表示と受付はホストの既存契約を使い、Applet側でenabledを書き換えたり、停止中の処理を直接走らせたりしない。

## 履歴ページの画面

旧説明パネルの外観は継承しない。画像を主役にした角丸カード、余白のあるヘッダー、モニターのタブ、簡潔な前後ボタンとページ番号を使う。開く／削除はアイコンと短いラベルを組み合わせ、削除確認はダイアログへ集約する。明暗テーマと狭幅に対応する。

| 順序 | 内容 |
| --- | --- |
| 1 | 見出し「最近使った壁紙」、履歴が実行中だけ保持される説明 |
| 2 | 「モニター1」「モニター2」…の選択。選択状態とキーボード操作を表示 |
| 3 | 選択モニターの件数、現在ページ、前のページ／次のページ／履歴を更新／壁紙の操作に戻る |
| 4 | サムネイル一覧。画像名、解像度、ファイルサイズ、元パスのツールチップ、画像を開く／画像を削除 |

先頭・末尾では該当ページ送りボタンを無効にする。履歴0件と履歴無効（historyLimit=0）を区別して案内する。モニターごとのページ位置を実行中だけ保持し、件数・設定・モニター構成が変わったら範囲内に収める。別ページから戻った場合とpage/windowの表示先切り替えでは、標準のView保持を使う。

サムネイルクリックはページ内のプレビューダイアログを開く。幅・高さともページの表示領域の60%とし、画像は縦横比を保って内側へ収める。周囲のグレーの背景をクリックすると閉じ、画像やダイアログ内部のクリックでは閉じない。元画像を開く操作とは分け、Esc・閉じる・フォーカス復帰を扱う。既存と同じ生成サムネイルを使い、プレビューのために原寸ファイルをブラウザーへ公開しない。元画像を開く処理は.NETで存在確認後、現在と同じOS関連付けを使う。

削除確認は「画像を削除」、対象パス、「ごみ箱へ移す」「キャンセル」を表示する。確認中の二重送信を防ぎ、成功後は同じパスを全モニターの履歴から除いて再取得する。削除失敗時は画像と履歴を維持し、安全な理由を画面と既存ホストログへ出す。確認取消は画像を変更しない。

画面は本体テーマに追従し、狭い幅では操作列を折り返す。サムネイルの遅延読込、長い画像名の折返し、ページ内の水平はみ出し、Tab順序、ダイアログのフォーカスを確認する。表示上のファイル名短縮は現在の設定に従い、内部の操作対象は省略しない。

順次読込の通知や画像を開く処理中も、表示済みのサムネイルは明るさとホバー時の拡大を保つ。操作を一時的に無効にしても画像の親ボタンを薄くせず、同じ表示世代では画像のDOMとURLを維持する。

画像名の行数にかかわらず「開く」「削除」の操作列はカードの下端へ寄せ、同じグリッド行では高さをそろえる。画像の縦横比と名前の折返しを維持し、余白は説明部分と操作列の間へ置く。

## ページ内操作とデータ

`pageActions`はこのApplet自身のlocalページ`history`だけで受ける。引数は共通契約のprimitive型で宣言し、件数・整数・範囲と表示世代は.NETでも検証する。次のidはコマンドIDではない。

| ページ操作id | 入力 | 結果・処理 |
| --- | --- | --- |
| `history.state` | なし | モニター一覧、選択位置、設定、履歴内容revision、読込状態 |
| `history.read` | `monitor:number, page:number, offset:number, limit:number, generation:string` | 空generationなら表示用の履歴スナップショットを確保。以後はその世代の区間を返す |
| `history.release` | `generation:string` | 表示用の画像参照とファイルを解放。繰り返しの解放は成功 |
| `history.open` | `generation:string, slot:number` | スナップショットに固定された元画像をOSで開く |
| `history.delete-request` | `generation:string, slot:number` | 対象を検証し、単回使用の確認tokenと表示用の対象パスを返す |
| `history.delete-confirm` | `confirmationToken:string` | tokenを消費してから既存のごみ箱処理を1回実行する |
| `history.delete-cancel` | `confirmationToken:string` | 確認を取消。元画像と履歴は保持 |

一覧の結果は世代、モニター、現在ページ、合計、ページサイズ、offset、nextOffset、itemsを持つ。各itemはslot、表示名、tooltip、画像情報、読込状態、準備済みなら登録画像のURLを持つ。UIから元画像パスや削除パスを指定させない。

1回の一覧は最大32項目かつ最終RPC形式で256KiB以内に収め、nextOffsetで続ける。長いパスやファイル名でも1MiBの通信上限を超えない。全1,000件を単一のJSON応答に集約せず、画像本体は共通のページ画像URLで読む。設定値の上限をこの分割に合わせて縮小しない。

履歴スナップショットの取得だけを短い要求で返し、サムネイルと解像度・サイズの読込は専用の直列workerで進める。未準備のitemは読込中として返す。結果が揃った区間の変更通知をまとめ、UIは表示中の区間を取り直す。画像I/Oの完了まで`page.action`を待たせず、標準15秒の要求待ちを延長しない。読込不能な画像は項目内エラーとし、一覧全体を消さない。

## 世代・画像・終了処理

- .NETがスナップショットを作り、slotと実パスを固定する。古い世代・範囲外slot・別ページからの操作は拒否し、別画像の操作へ読み替えない。
- UIは要求番号を持ち、最新の表示要求だけを反映する。古い応答は捨て、その世代を解放する。モニター／ページ切り替えと設定変更の遅延応答で選択状態を巻き戻さない。
- 通常のサムネイル準備通知ではスナップショット世代を変えない。履歴内容の更新、明示更新、ページ・モニター・サムネイル設定の変更で新しい表示世代を作る。
- 旧一覧を表示しながら新一覧を準備できるよう、保持は最大2世代。UIからの連続要求は最新の行き先へまとめ、古いworkerの結果を適用しない。workerは同時に増やさない。
- 削除確認中の通常の履歴追加は表示更新を保留し、確認対象を固定する。ページ切り替え・明示更新・対象世代の解放では確認tokenを失効させる。取消／失敗後は最新状態を取り直す。
- 確認tokenは実行前に消費し、同じtokenで再実行しない。結果不明・タイムアウト・接続切断時に削除を自動再送せず、表示の再取得とログ確認につなぐ。

サムネイルは現在と同じPC専用imageDirectory配下の、自身の実行用サブフォルダーにPNGで作る。幅・高さ1～2,048px、表示名1～1,024文字、historyPageSize 1～1,000件、historyLimit 0～1,000件を維持する。画像生成・共通登録は小分けにし、新しい参照を画面へ渡してから旧参照と旧ファイルを解放する。

`home`、自身が呼ぶページの明示破棄、Applet停止では履歴用の確認・worker・生成画像を回収する。単なる別ページ移動・非表示・page/window載せ替えではViewの入力と必要な参照を保持する。View破棄後の再openは画像参照を取り直す。予期しないView破棄では共通基盤が参照を即時失効させ、.NETに残る最大2世代の生成物は次のデータ取得または停止時に回収する。HTMLのunload通知だけを終了処理の根拠にしない。

`home`は生成画像の回収後に古いHTMLが残らないようViewも破棄する。モニター別のページ位置は.NETの実行中状態に残せる。自身のView破棄に伴うUI側の応答消失を削除操作などの自動再実行につなげない。

停止はworkerの取消と世代失効を先に行い、遅いファイルI/Oの終了を無期限に待たない。遅れて生成した結果は画面へ出さず、自分のファイルだけを片付ける。既存の2秒の停止猶予、セッション終了時のエンジン解放とホストログ排出を維持する。

履歴は現在と同じ実行中だけの情報とし、永続履歴・ページ位置用の保存ファイルを追加しない。`settings.json`の既存値と保存先、モニター設定、paused、旧ファイル、Windows背景・Themesキャッシュを変更する処理は加えない。ページ表示先とWindow位置は本体の既存保存契約を使う。
