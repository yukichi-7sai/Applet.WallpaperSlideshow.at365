# 壁紙履歴ページ

共通の保存先・元画像の権限・表示寿命は[メモリStorageと元画像表示](../../AppDock.at365/docs/memory-storage.md)、ページ登録は[Appletページ](../../AppDock.at365/docs/applet-pages.md)を正本とする。本書はWallpaperSlideshow固有の分担と操作を扱う。

## 処理の分担

- `web/history-gallery.js`とCSSは履歴専用の表示部品。本体のギャラリーから独立して所有・編集し、ビルド時の取り込みや版同期は行わない。カード一覧・180〜360pxのサイズ操作・拡大表示・遅延読み込み・表示位置とフォーカスの維持・終了時の回収を担当する。本体向けの複数選択・矩形選択・ドラッグ整理は含めない。
- モニター選択・ページ送り・自動更新・元画像を開く／削除する処理とダイアログは`history.js`、画像参照とBlob URLの寿命は`memory-images.js`が引き続き担当する。保存形式とホストの公開APIは変更しない。
- `history-navigation.js`はカードの単一選択と、プレビューを開いた時点のモニター内の並び順・移動位置を管理する。同じパスの重複は出現順を含むIDで区別する。選択はView内だけの状態とし、設定やStorageへ保存しない。

- .NETはWindowsの背面描画、再生制御、履歴パスの記録を担当する。履歴ページ用の画像を読み込み・縮小・保存しない。
- `HistoryPublisher`は履歴のパス一覧を共通Storageの`Memory` scopeへ公開する。専用の履歴ファイルや画像キャッシュは作らない。
- HTML/JavaScriptの履歴ページはStorageから一覧を読み、共通の元画像参照を通して元ファイルを取得する。縮小画像はCanvasとBlob URLで作り、このページの表示中だけ保持する。
- Node.jsはAppDock本体のStorage・ファイル配信を担当する。Applet専用の追加Nodeプロセスや.NETとの画像RPCは設けない。

ページID、リボンID、開くコマンドは`history`、`page:at365.wallpaper-slideshow:history`、`at365.wallpaper-slideshow.history`を維持する。capabilityは`ui/settings/storage/source-images/pages`。半透明背景の共通CSS変数を使うため、最低ホスト版は0.140.0。

## メモリに公開する履歴

`.NET HistoryManager`はモニターごとの新しい順のパス一覧とrevisionを持つ。正常に背面へ表示したフレームを履歴へ追加してから公開する。履歴件数の削減・モニター変更・削除にもrevisionを進める。

索引キー`history`は`schemaVersion/revision/generation/monitors`を持つ。各モニターには`count`と、パス配列を保存したメモリキーの`chunks`を持たせる。文字数の長い1,000件でも既存RPCへ収まるよう、区間はシリアライズしたJSONで約240KiB以内へ分割する。全区間を保存してから索引を置き換え、旧区間は`null`で解放する。索引保存が拒否された場合は以前の索引を維持する。受付結果が不明なら、保存済みかもしれない区間を削除せず、次の索引保存に成功した後または停止時に回収する。

ページは表示開始時に1世代のパス一覧をメモリへ取得する。取得前に`history-snapshot`キーへ保持する世代を公開し、索引を再確認する。取得中に索引世代が変われば新しい索引を読む。置き換え中は表示済みと取得中の両世代を保持し、取得失敗・受付不明でも現在の一覧の区間を失わない。`HistoryPublisher`は保持対象の旧区間を回収せず、解除後の次回公開・状態反映時に回収する。選択位置は`history-view`キーへJSからメモリ保存し、View再生成でも同じApplet実行中なら復元する。停止・異常終了・再起動ではホストが全メモリ値を解放する。

自動更新は既定OFF。OFFでは背景の履歴公開で表示用一覧を置き換えず、ページ送り・モニター切替も同じ世代を参照する。更新ボタンで最新世代を取得して元画像を読み直す。ONへの切り替えは即時更新し、以降は新しい世代へ追従する。OFFへの切り替えは進行中の取得も失効させ、遅延結果で表示を変えない。明暗・表示サイズなどの明示変更は従来どおり反映する。

履歴件数0～1,000件、1ページ1～1,000件、サムネイルの各辺1～2,048px、表示名1～1,024文字という既存設定は維持する。履歴はパスだけで、元画像の内容を過去の状態として保存しない。

## 表示と画像の寿命

履歴専用ギャラリーへ表示中ページの項目を渡し、表示領域付近から画像を取得する。元画像の解像度・ファイルサイズは読込結果から表示する。ファイル名は設定に沿って短縮し、ツールチップと操作対象の実パスは省略しない。プレビューでは表示中の1枚を追加取得し、ページ外の画像は次へ移った時点で解放する。全履歴の画像を先読みしない。

`sourceImages.register`には.NETが公開した区間キー、区間内のJSON Pointer、取得済みパスを渡す。取得不能なら項目を画像なしの状態にし、古い画像を表示しない。明示更新と再表示では元ファイルから読み直す。通常の履歴追加では同じパスの生成済み画像を再利用し、画像のDOM・URL・明るさを不要に変えない。

モニター／ページ移動では不要になった画像・元ファイル参照を解放する。非表示、別ページへの移動、Windowの×、最小化、View破棄では、取得を取り消してBitmapを閉じ、Canvasを空にし、Blob URLとDOM参照を解放する。読込・decodeの遅延結果で閉じた画面の画像を再生成しない。page/windowの載せ替えでは同じViewとダイアログを保持する。

非表示ではページが保持する一覧・画像を解放して世代の保持解除を要求し、再表示時に一覧と元画像を読み直す。「設定を開く」も通常の画面移動と同じ非表示処理を使う。保持解除した旧区間は.NET側の次の履歴公開時に回収する。OSのメモリ使用量の即時減少は参照解放とは区別する。既存のキャッシュファイル全体や旧Local/Roaming領域は自動削除しない。

## 操作

モニター別の件数とページ位置を扱い、先頭・末尾では前後ボタンを無効にする。履歴0件と無効設定は別の案内を出す。設定・件数・画面構成の変更で位置が範囲外なら範囲内へ収める。

サムネイルから開くプレビューはページ領域の幅・高さの85%。タイトルはカードの表示文字数設定と独立した省略前のファイル名を使い、長い名前は折り返して閉じるボタンを保持する。画像比率を保ち、修飾キーなしの←/→と画像表示領域の左右端ボタンで前後へ移動する。同じモニターの表示順でページをまたぎ、先頭・末尾では止まる。現在位置/総件数を表示し、移動できない端のボタンは非表示・無効にする。中央クリックやドラッグでは移動・閉鎖しない。

プレビュー中は一覧の更新を保留し、開いた時点の順序を維持する。読み込み中も移動でき、遅れて完了した画像で移動先を上書きしない。元画像が読めない項目はエラーを表示したまま前後へ移動できる。背景・閉じるボタン・Escで閉じると保留中の更新を反映し、最後に見た項目の現在のページへ戻してカードへフォーカスを移す。対象が履歴から消えていた場合は近いページへ戻し、選択を解除する。

クリックしたカードは単一選択にして、カード全体の枠をアクセント色で表示する。プレビュー移動でも選択を更新し、背景クリックで閉じた後や他の操作へフォーカスを移した後も選択枠を残す。キーボードフォーカスは選択と別に示し、画像ボタンのフォーカスはカード外枠へ、開く/削除は各ボタンへ表示する。

選択が変わったときは、カードが表示領域へ収まる最小限の距離だけ即時スクロールする。プレビューでページをまたいだ場合も、開いた時点の一覧から該当ページを表示して選択位置へ追従する。背後の一覧へフォーカスは移さず、プレビューのキー操作を保つ。選択後の手動スクロールや通常の画像読み込みでは選択位置へ引き戻さない。

「開く」は固定された元画像参照をOSの関連付けへ渡す。「削除」は対象パスと確認/キャンセルを表示する。通常の画像は「ごみ箱へ移す」、ホストがネットワーク画像と判定したものは「削除する」とし、Windowsのごみ箱に入らず元に戻せない可能性を明示する。確認を消費してから、前者は`sourceImages.trash`、後者は`sourceImages.delete`を1回だけ送信する。ごみ箱の失敗から直接削除へ自動で切り替えない。成功後の`IPageFileHandler`通知で.NETは同じパスを全モニターから取り除き、パス一覧を再公開する。確認中は通常更新を保留し、失敗時は元ファイルと履歴を保持する。結果不明の削除を自動再送しない。

確認して削除した画像は、OFFでも表示用一覧の全モニターから除く。背景で増えた履歴をこの操作へ混ぜない。右上の「設定を開く」は既存のhomeコマンドから`Ui.OpenSettingsAsync`へ取り次ぎ、コマンドパレットと同じ本体の設定コマンドでWallpaperSlideshowの設定本文を開く。移動前のView破棄や別の画面移動は行わず、本体内の履歴ページと設定を「戻る」「進む」各1回で往復できる。独立Windowもパレットと同じ動作とし、表示中の履歴Windowは維持する。停止時のエンジン解放、WM_ENDSESSION、2秒の終了猶予、共通ログへの排出は維持する。Windowsの壁紙設定やThemesキャッシュは読み書きしない。

画面は共通の配色・スクロールバーと明暗テーマを使う。長い名前は折り返し、同じ行の操作列をカード下端に揃える。狭幅、キーボード操作、確認後のフォーカスを維持する。

プレビューと削除確認の背景・影は[共通の表示設定](../../AppDock.at365/docs/appearance.md)へ表示中も追従する。`dialog::backdrop`の背景とブラーは共通CSS変数を参照し、透明・半透明・ブラーを反映する。影OFFは共通data属性で反映する。削除確定ボタンは文字だけを中央に置き、ページ下部に実行中だけの保持を案内する文言は置かない。

## 表示サイズ

カード幅と自動更新は共通Storageの`gallery-view`キーを端末別ファイルscopeへ保存する。schemaVersion 1、cardWidthは180～360 CSS px、20px刻み、初期260pxを維持する。任意のautoRefreshはbooleanで、省略時はfalse。従来のカード幅だけのデータも読み、初回取得では保存しない。初期読込を共有し、保存を直列化して片方の操作で他方の値を失わない。保存失敗の値は画面で保持して明示再試行し、破損・未知形式の値を上書きしない。履歴パスや画像のメモリ保存と分離し、サムネイル寸法・壁紙設定・他のギャラリーの表示サイズを変えない。
