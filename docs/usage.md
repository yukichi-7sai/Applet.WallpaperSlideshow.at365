# Applet.WallpaperSlideshow.at365 機能・操作・設定

デスクトップの画像をメモリ内で合成・表示するWindows用Appletです。**AppDock 0.140.0以上**が必要です。

「壁紙のスライドショー」と「更新間隔」の設定をCodex連携へ公開します。スライドショーは既定ONで、ONは再生、OFFは停止です。ON/OFF/切り替えコマンドは設定定義から自動生成され、ショートカットにも割り当てられます。設定変更にはコマンド実行・設定変更の両許可が必要です。「次の壁紙」はコマンド実行許可だけで利用できます。

## 導入・更新

合成画像をメモリから背面ウィンドウへ表示し、Windowsの壁紙設定を変更しません。表示用BMPの保存も行いません。エラーログはAppDockの「ログ」ページと、このAppletの詳細にある「ログ」タブに表示します。旧APPDATA内のファイルや以前の`errors.log`は自動移動・削除しません。壁紙フォルダーの元画像とAppDockの共有設定はこれまでどおりです。

1. AppDockをトレイの「終了」から完全終了します。
2. 配布物の `extension.json`、`Applet.WallpaperSlideshow.at365.exe`、`web`フォルダーを、AppDock.at365.exeの隣の `extensions/Applet.WallpaperSlideshow.at365/` に配置します。更新時も配布物一式をそろえて置き換えてください。
3. AppDockを起動し、「Applet」一覧で有効にします。操作やキーの割り当てはAppDockから行います。

利用するPCにはAppDockの動作環境が必要です。詳細は[AppDockの導入案内](../../AppDock.at365/docs/usage.md)を参照してください。

このAppletの配布EXEには必要なランタイムが含まれています。元のWallpaperSlideshowと同時に再生しないでください。

## 設定

AppDockの「設定」→「Applet.WallpaperSlideshow.at365」で、JSONを直接書かずに設定できます。

- 「モニターごとの画像設定」は共通の一覧で表示します。番号・画像ソースフォルダー・表示モード・タイル枚数を確認でき、歯車で詳細を編集します。「モニターを追加」も同じダイアログを使い、OKで保存、キャンセルで入力を破棄します。
- モニター番号は左から右、同じX位置では上から下の画面順です。並べ替えボタンで設定を割り当てる順序を変更できます。ゴミ箱から削除する際は確認が表示されます。
- モニターごとに画像ソースフォルダーを複数追加でき、Windowsのフォルダー選択も使えます。各64件まで。
- **表示モード・タイル枚数・タイル間の余白・上下左右のPaddingはモニターごとの設定**です。Fill / Fit / Stretch / Center / Tile、タイル1～64枚、タイル間の余白0～4096px（既定10px）、Padding 0～65535px。タイル枚数とタイル間の余白はTileのときだけ編集でき、他のモードでも値を保持します。実際の画面サイズを超える余白はエラーにします。
- 壁紙のスライドショー（既定ON）、更新間隔、履歴の保存件数、サムネイルの幅・高さ、ファイル名の表示文字数をフォームで変更できます。元アプリの範囲（サムネイル1～2048px、ファイル名1～1024文字）を維持しています。
- 「最近使った壁紙の1ページの表示件数」は**既定4件、1～1000件**です。モニターごとの履歴保存件数（既定30件、0～1000件）とは独立しています。

フォルダー内のJPEG / PNG / BMPとサブフォルダーの画像を使います。重複フォルダーや親子フォルダーの画像を重複排除し、1巡するまで同じ画像を選びません。存在しないフォルダーや共有の復旧を監視し、アクセスできるほかのフォルダーは使えます。サブフォルダーのジャンクション・シンボリックリンクはたどりません。

通常のファイル変更通知に加えて、自動更新・「次の壁紙」・再生再開時に、フォルダーの存在と監視の再接続を確認します。起動時と設定変更時にも確認します。停止中は定期的な補助確認を行いません。フォルダーの復帰確認の頻度は壁紙の更新間隔に従い、確認結果が次の壁紙更新で反映される場合があります。画像一覧全体を毎回走査する処理ではありません。

設定はAppDockの`settings.json`内の`extensions["at365.wallpaper-slideshow"].settings`へ保存し、元アプリの設定は変更しません。不正な画像設定はログとパネルに表示し、前回の有効設定を維持します。旧`Mode`の数値表現も引き継ぎます。

## デスクトップへの表示

画像はデスクトップのアイコンより後ろに表示します。Windowsの背景を「画像・スパン」に準備する必要はありません。画像切り替えによる壁紙設定の書き換えと表示用BMP保存を廃止したため、旧prepare-backgroundコマンド・ボタンは削除しました。既存の割当は自動で別操作へ振り替えません。「Windowsの背景設定を開く」は、停止中に見えるWindows側の背景を確認するために使えます。

背面への配置はExplorerの構成に依存します。接続できない場合は操作画面に再接続待ち・表示エラーを表示し、Windowsの背景をそのまま維持します。「次の壁紙」で再試行できます。画像を保持するためのメモリは表示解像度に応じて使用します。

## 遅延開始とコマンド

AppDock共通の「開始までの秒数」は**既定30秒**。有効化・AppDock起動・Applet再起動から指定秒数後に、Appletのプロセス自体を起動します。0で即時、最大86400秒。開始待ちの画面に予定時刻と「今すぐ開始」を表示します。無効化・AppDock終了で予約を取り消し、待機中の秒数変更ではそこから待ち直します。

コマンドはAppDockのパレット・ピン留め・ショートカットで使用します。生成コマンドはAppletの起動前からキーを設定できますが、実行は有効・稼働中に限ります。Appletを有効化し、必要なら「今すぐ開始」を押してください。旧start/stop/toggle/resume/pauseは廃止しました。既存のキー・トレイ・ジェスチャー割当は、新しいコマンドへ割り当て直してください。

| ID末尾                   | 操作                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| `settings.slideshowEnabled.on`    | 開始／再開。手動停止を解除し、再生中なら維持                         |
| `settings.slideshowEnabled.off`     | 停止。現在の壁紙を消去し、再生OFFを保存                             |
| `settings.slideshowEnabled.toggle` | 再生ON/OFFを反転して保存                                           |
| `next`                   | 次の壁紙に更新                                                       |
| `history`                | 最近使った壁紙の独立ページを開く                                     |
| `home`                   | 本体の共通設定コマンドでWallpaperSlideshowの設定を開く                |
| `data`                   | データフォルダーを開く                                               |
| `background-settings`    | Windowsの「個人用設定 → 背景」を開く                                 |

IDの接頭辞は`at365.wallpaper-slideshow.`です。旧`resume`/`pause`の別名も廃止し、生成コマンドへ統一しています。画像ごとの「履歴1を開く」等はコマンド登録せず、履歴ビュー専用のボタンで処理します。

手動停止は保存され、ロック解除で勝手に再開しません。ロック・リモート接続による停止は手動停止と独立しています。停止中の「次の壁紙」は切り替えず、開始もロック・リモート接続による停止を解除しません。不正な画像設定があっても前回の有効設定で開始・停止できます。停止・無効化・終了では表示ウィンドウと画像メモリを解放し、その時点でWindowsに設定されている背景が見えます。Windowsの壁紙設定は変更しません。

## 最近使った壁紙

リボンの「最近使った壁紙」、または「最近使った壁紙を開く」コマンドで開きます。画像カードとシンプルな操作ボタン、ページ送りを備え、本体の明暗テーマに追従します。Appletの説明には通常の壁紙操作と状態を表示します。履歴の表示先はApplet設定から本体内／別ウィンドウを選べます。

右上の「設定を開く」は、コマンドパレットの「WallpaperSlideshowの設定を開く」と同じ経路で設定へ移ります。本体内の履歴ページから移動した場合は、「戻る」1回で履歴へ、「進む」1回で設定へ戻れます。独立Windowで表示している履歴はそのまま残ります。プレビューと削除確認の背景・影は、AppDockの「ダイアログ・パレットの背景」「ダイアログ・パレットの影」に従い、開いている間の変更も反映します。設定画面の「停止」の説明にあるコマンドリンクは、対象を選んだパレットを開きます。実行を選ぶまでは停止状態を変えません。

履歴のページ送りは一覧の前後ボタンを使います。

履歴の上部にある**モニター1 / モニター2…**で切り替えます。各モニターの件数とページ位置を別々に扱います。履歴は実行中だけパスを保持し、Applet終了で消えます。0件設定で履歴を無効化できます。

**自動更新**の初期状態はOFFです。OFFの間は、裏で履歴が増えても表示中の一覧・件数・ページ送りの対象を変えません。「更新」で最新の履歴と元画像を読み直します。ONに切り替えるとすぐ最新を表示し、その後の変更にも追従します。切り替えた状態はこのPCで記憶します。履歴を閉じて開き直したときは、保存したON/OFFで最新の履歴から始めます。自分で削除した画像はOFFでも表示から取り除きます。

各画像にサムネイル、解像度・ファイルサイズ、元ファイルパスのツールチップ、「開く」「削除」を表示します。AppDockの画像ライブラリーと共通のカードを使い、ページ内の「画像サイズ」で大きさを調整できます。サイズはこのPCで記憶し、サムネイルの生成解像度・壁紙の再生設定・ライブラリーの表示サイズには影響しません。

サムネイルをクリックすると、ページの幅・高さの85%のプレビューを開き、タイトルに省略前のファイル名を表示します。背景は本体の「ダイアログ・パレットの背景」の透明・半透明・ブラーに追従します。**←/→キー**または画像表示領域の**左右端の矢印**で前後の画像へ移動できます。同じモニターの履歴をページをまたいでたどり、先頭・末尾では止まります。開いている間は並び順を保ち、現在位置と総件数を表示します。画像中央のクリックやドラッグでは閉じません。

周囲の背景、閉じるボタン、Escで閉じると、最後に見た画像のページへ戻ります。クリックしたカードや最後にプレビューしたカードは、**カード全体の枠**で選択状態を示し、ほかの場所へフォーカスを移しても枠が残ります。選択は画面内だけの状態で、再起動後には保存しません。履歴の更新でその項目がなくなった場合は選択を解除します。

選択が変わると、そのカードが見える分だけ一覧が自動でスクロールします。プレビューで別のページの画像へ進んだ場合も、背後の一覧が該当ページとカードへ追従します。選択後は自由に手動スクロールできます。

削除は対象の元ファイルを確認する画面を表示し、通常の画像は「ごみ箱へ移す」で実行します。NAS・ネットワーク共有の画像は、Windowsのごみ箱に入らず元に戻せない可能性を表示したうえで「削除する」で実行します。キャンセルも可能です。成功時は同じパスをすべてのモニターの履歴から除き、表示を更新します。古いページのボタンでは別の画像を操作できません。

削除失敗時はファイルと履歴を維持します。ごみ箱への移動が失敗しても、直接削除へ自動で切り替えません。NAS側で削除した画像を復元できるかどうかは、NASの設定によります。

## データの保存先

履歴カードの表示サイズはAppDockの端末別Storage（`data/storage/at365.wallpaper-slideshow/devices/<端末名>/gallery-view.json`）に保存します。初めてサイズを変更したときに作成し、再起動後も復元します。保存できなかった場合は画面に表示し、「保存を再試行」でやり直せます。破損・未知形式のデータは自動で上書きしません。

表示画像はメモリ内で合成し、表示用BMPやWindowsのThemesキャッシュへの保存は行いません。履歴のパス一覧とページ位置はStorageのメモリ保存を使い、JSONや履歴画像をファイルへ書き出しません。元画像は表示時に読み、読めない場合は画像を表示しません。ページを閉じる・別ページへ移る・最小化すると表示用画像を解放し、再表示時に読み直します。エラーログはAppDockへ保存します。旧Local/Roaming領域や旧BMPは自動移動・削除せず、「データフォルダーを開く」は従来フォルダーを開きます。

## 手動設定の例・更新の確認

保存されるモニター設定の形式例です。通常の設定操作には上記のフォームを使ってください。

```json
[
  {
    "Folders": ["C:/Wallpapers/Art", "C:/Wallpapers/Photos"],
    "Mode": "Tile",
    "TileCount": 13,
    "TileMargin": 10,
    "PaddingLeft": 1,
    "PaddingRight": 1,
    "PaddingTop": 1,
    "PaddingBottom": 40
  },
  {
    "Folders": ["C:/Wallpapers/Portrait"],
    "Mode": "Fit",
    "PaddingLeft": 1,
    "PaddingRight": 1,
    "PaddingTop": 1,
    "PaddingBottom": 1
  }
]
```

更新元の既定値は`github:yukichi-7sai/Applet.WallpaperSlideshow.at365`です。AppDockの「バージョン情報・更新」ページから、正式リリースを確認して更新できます。起動時の更新確認ではダウンロード・適用を行いません。

## AppDockからの更新

「設定 → バージョン情報・更新」の一括更新、またはこのAppletの個別更新ボタンを利用できます。配布元が`update.json`と`update.zip`を提供している場合に対応します。更新元は「インストール済みのApplet」の「更新元の設定」で変更し、保存してください。ローカルフォルダー・UNC・HTTP(S)・GitHub Releaseに対応し、「既定に戻す」も利用できます。

更新内容を確認して再起動すると配布ファイル一式を交換します。AppDock側の設定・有効状態・保存データは保持します。詳細は[AppDockの更新操作](../../AppDock.at365/docs/usage.md#アップデート)を参照してください。

開発・ビルドについては[開発ガイド](../DEVELOPMENT.md)を参照してください。

## 公開設定の拡充

Codexから壁紙のスライドショー・更新間隔に加え、履歴件数、サムネイルの幅/高さ、ファイル名の表示文字数、1ページの表示件数を取得・変更できます。履歴件数を減らすと実行中の古い履歴は削られますが、元画像は削除しません。モニターごとの画像フォルダーや表示方法は設定画面から編集してください。必要な本体版は0.140.0です。

## 共通の設定画面

AppDockの「設定」またはApplet詳細の「設定」タブで、スライドショー・モニターと画像・履歴の表示・Windowsの背景のカードから編集できます。本体と同じテーマ・入力欄・自動保存を使い、起動待ちは末尾の共通カードにあり、ページを持つAppletでは表示方法も設定できます。既存の設定値・コマンドIDは引き継ぎます。履歴とWindows背景の操作は見出しを押すと開き、横断検索からも対象項目へ移動できます。
